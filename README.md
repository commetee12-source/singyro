# 신규는 여기로

서울시교육청 신규 교육행정직을 위한 반응형 업무 길잡이입니다. 개인 제작 사이트이며 교육청 공식 서비스가 아닙니다.

공개 사이트: [신규는 여기로](https://singyro-seoul.netlify.app/) · 최초 배포: 2026-09-11

## 실행

Node.js 22 이상에서 프로젝트 폴더를 열고 실행합니다.

```powershell
npm ci
npm run dev
```

브라우저에서 http://127.0.0.1:5173/ 을 엽니다. 서버를 종료하면 이 주소로 접속할 수 없습니다.

```powershell
npm run build
npm run preview
```

`dist` 폴더가 정적 배포 결과입니다. Netlify는 이 폴더를 게시하도록 `netlify.toml`을 구성했습니다. **Netlify의 singyro-seoul 프로젝트에 공개 배포되어 있습니다.** HTML 파일을 직접 더블클릭하는 방식은 지원하지 않습니다.

## 공개 사이트 갱신

자료나 디자인을 수정한 뒤 이 프로젝트 폴더에서 다음 명령을 실행합니다. Netlify 계정 로그인이 필요합니다.

```powershell
npm run build
npx --yes netlify deploy --prod --no-build --dir dist --functions netlify/functions --site b5108832-b61b-4150-bcf6-c0653c338a62
```

빌드 성공 후 배포 명령을 실행하세요. 주소는 그대로 유지됩니다. 현재 배포는 로컬 파일을 업로드하는 방식이며 Git 저장소 자동 배포는 연결하지 않았습니다.

**`--functions netlify/functions` 를 빼먹지 마세요.** 방문자 카운터가 이 함수로 동작하므로, 빠뜨리면 배포는 되지만 카운터만 조용히 사라집니다.

- 길잡이 상세, 근거 링크, 개별 링크 공유, AI 질문문 복사
- 지식카드 상세: 원문 라벨(전국 공통·서울교육청 고유·내부확인 필요), 검증 지적사항, 마크다운 본문, 적용범위·갱신주기

- 오늘/누적 방문자 수(사이드바) — Netlify Functions + Blobs, 브라우저당 하루 1회 집계
- 업무 용어 12개
- 공식 원문 링크 4개 + 공식 자료·허브 58개 + 법령·자치법규 35개(2026-09-13 조사) + 개인 파일·링크 자료실

## 지식창고 초안 카드 (2026-09-15 반영)

`wiki/syntheses/신규 지식창고/`의 84장 카드 초안을 `scripts/build-cards.py`가 `src/knowledge-cards.ts`로 변환합니다. 자비스5 독립 검증(2026-09-13)이 「현 상태 공식 게시 불가, 참고사이트 시범 탑재는 수정 후 가능」으로 판정했으므로, 카드는 모두 **초안·검토 전** 상태로 표시하고 지적사항을 카드마다 함께 보여 줍니다. 자세한 내용은 `docs/KNOWLEDGE-CARDS.md`를 보세요.

```powershell
python scripts/build-cards.py      # 카드 초안 JSON → src/knowledge-cards.ts
python scripts/build-manuals.py    # 자료 조사표 xlsx → public/manuals.json
npm run build
```

생성 파일은 직접 고치지 말고 원본 JSON·xlsx 또는 스크립트의 반영표를 고친 뒤 재실행합니다.
- 개인 자료 추가·수정·다운로드·삭제·되돌리기
- 첨부파일을 포함한 JSON 백업·복원(기존 ID가 있으면 덮어쓰지 않고 건너뜀)
- 모바일 메뉴, 키보드 탐색, 기본 모달 포커스 관리, 동작 축소 설정

## 추후 매뉴얼 추가

### 개인적으로 사용할 자료

사이트의 **매뉴얼·자료실 → 자료 추가**에서 파일이나 HTTPS 원문 링크를 등록하세요.

- 지원: PDF, HWP/HWPX, DOC/DOCX, XLS/XLSX, PPT/PPTX, TXT, MD
- 파일당 20MB, 개인 자료 파일 합계 100MB
- 파일은 IndexedDB, 즐겨찾기·체크 상태는 localStorage에 저장
- 같은 기기라도 브라우저나 접속 주소가 다르면 기록이 분리됨
- 브라우저 데이터 삭제 시 기록 소실 가능
- **자료 백업**은 자료와 파일만 포함. 즐겨찾기·체크 상태는 미포함
- 파일 내용 자동 추출·본문 검색·AI 답변 생성 기능은 아직 없음
- 서버 업로드, 계정, 기기 동기화, 여러 이용자 공유 기능은 없음

### 모든 이용자에게 제공할 공통 자료

1. 공개 가능한 매뉴얼을 `public/manuals/`에 넣습니다. 파일명은 영문·숫자·하이픈 사용을 권장합니다.
2. `public/manuals.json` 배열에 다음 형식의 항목을 추가합니다.
3. `npm run build` 후 배포 결과를 갱신합니다.

```json
{
  "id": "seoul-contract-2026",
  "title": "서울교육 계약업무 매뉴얼",
  "category": "contract",
  "description": "등록한 실제 자료의 적용 범위와 개정 내용을 입력합니다.",
  "publisher": "실제 발행기관",
  "year": "2026",
  "addedAt": "2026-09-11",
  "url": "/manuals/contract-2026.pdf"
}
```

위 항목은 **등록 형식 예시**이며 해당 파일이 기본 제공되지는 않습니다. 원문 게시물 HTTPS 주소를 넣어도 됩니다. 배포되는 public 폴더는 누구나 접근할 수 있으므로 공개 가능한 자료만 넣습니다.

분야 ID: `start` 첫 출근, `service` 복무, `budget` 회계, `contract` 계약, `payroll` 급여, `systems` 시스템, `documents` 문서, `school` 학교행정.

## 법령·지침 확인 범위

초기 검색일: **2026-09-11**. 출처는 사이트 내부 각 카드 및 `docs/SOURCES.md`에 기록했습니다. 실제 안내는 실무 입문용 확인 목록입니다. 금액·휴가 일수·수의계약 한도·시스템 메뉴 경로는 임의로 확정하지 않았습니다. 학교회계와 교육비특별회계, 지방공무원과 교원·교육공무직을 구분합니다.

공식 자료 링크가 있다는 사실과 세부 절차가 검증되었다는 판단을 구분합니다. 내용은 자동 갱신되지 않으므로 운영 시 정기 검토가 필요합니다.

## K-에듀파인 페이지

별도 메뉴 **에듀파인 따라하기**(`/#edufine-access`) 안에서 **지출관리시스템**, **수입관리시스템**, **예산관리시스템**, **사업관리시스템**을 선택합니다. 업무별 공개 매뉴얼 화면을 보고 단계별로 연습하며, 처음 접속 안내(업무망 5단계·외부 EVPN 8단계)도 이용할 수 있습니다. 기존 **K-에듀파인 → 지출 → 지출관리시스템 → 따라하기** 경로와 홈·용어사전·자료실 구성은 유지합니다. 구현과 출처·검증 범위는 [에듀파인 따라하기 문서](docs/EDUFINE-ACCESS.md), [수입관리 추가 문서](docs/EDUFINE-INCOME.md), [예산관리 추가 문서](docs/EDUFINE-BUDGET.md), [사업관리 추가 문서](docs/EDUFINE-PROJECT.md)를 참고하세요.

`src/edufine.ts`(데이터) + `src/EdufinePage.tsx`(화면). 구성은 서울시교육청 교육행정 지침 챗봇 **AI-SEN**(chatbot.aisen.store)의 공개 사용설명서에서 3탭 격리·슬래시 명령어·단어 정제기 개념을 참고했습니다.

**화면 절차(메뉴 위치·버튼 순서)는 일부러 비워 두었습니다.** 서울시교육청 최신 K-에듀파인 매뉴얼 원문을 확보하기 전까지는 채우지 않습니다. 타 시도·지난 연도 매뉴얼을 옮겨 적으면 신규자가 없는 화면을 찾아 헤매고, 이 사이트의 다른 카드가 지키는 출처 규칙도 무너집니다. 원문을 확보하면 `edufineTerms` 옆에 절차 데이터를 추가하고 `EdufinePage`의 「화면 절차는 아직 싣지 않았습니다」 블록을 교체하세요.

용어 9건 중 5건은 법령 원문으로 근거를 확인해 `basis` 필드에 조문·시행일·링크를 붙였습니다(지방회계법 제28·29·30조, 지방재정법 제45조 단서). 나머지 4건은 시스템 처리 단계의 이름이라 법령 근거가 없으므로 `caution` 으로 그 사실을 밝혔습니다. **근거 없는 항목에 조문을 추정해 붙이지 마세요.**

## 방문자 수 카운터

`netlify/functions/visits.mts` + `src/visits.ts` + `src/VisitCounter.tsx`.

- 저장소는 Netlify Blobs(`singyro-visits` 스토어, `counter` 키) 하나뿐입니다. **IP·User-Agent 등 개인 식별 정보는 저장하지 않고** 일자별·누적 숫자만 둡니다.
- `GET /api/visits` 는 읽기만, `POST /api/visits` 만 숫자를 올립니다. 크롤러·프리페치의 GET 으로 수치가 부풀지 않게 하기 위함입니다.
- 브라우저는 `localStorage` 의 `singyro-visit-day` 로 하루 한 번만 POST 합니다. 같은 날 여러 번 열어도 1 로 셉니다. 따라서 「오늘 방문자 수」는 정확히는 **오늘 이 사이트를 연 브라우저 수**입니다.
- 집계 날짜는 서버·클라이언트 모두 UTC+9(한국) 기준으로 맞췄습니다.
- 함수가 실패하거나 Blobs 를 못 쓰면 카운터는 **아무것도 그리지 않습니다.** 오류 문구 대신 조용히 사라지는 쪽이 낫기 때문입니다.
- 일자별 기록은 최근 45일만 보관합니다(`KEEP_DAYS`).
